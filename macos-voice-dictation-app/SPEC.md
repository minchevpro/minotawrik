# Спецификация: macOS-утилита голосового ввода на базе OpenAI

Статус: **план/спецификация, код ещё не пишется**.
Дата: 2026-07-01.

## 0. Идея продукта

Нативное macOS-приложение, живущее только в строке меню (menu bar, без иконки в
Dock). По глобальной комбинации клавиш (настраивается пользователем) в любом
месте системы появляется маленький плавающий индикатор микрофона. Пользователь
говорит, приложение отправляет аудио в OpenAI (`/v1/audio/transcriptions`,
модель по умолчанию — `gpt-4o-transcribe`, с возможностью сменить на
`gpt-4o-mini-transcribe` или `whisper-1`) и получает сырой текст **без**
дополнительной GPT-очистки. Текст:

1. всегда копируется в буфer обмена;
2. если в фокусе есть текстовое поле — автоматически вставляется в позицию
   курсора.

Все распознавания сохраняются в локальную историю (просмотр, поиск, удаление,
полная очистка).

Распространение — напрямую (нотариизированный DMG, без Mac App Store). Это
решение снимает ограничения App Sandbox и позволяет использовать классическую
связку Accessibility (TCC) + CGEvent + AXUIElement для глобальных хоткеев и
вставки текста в чужие приложения.

## 1. Технический стек и архитектура

### 1.1 Платформа и язык
- **Swift** (актуальная стабильная версия).
- **Гибрид AppKit + SwiftUI**:
  - AppKit — оболочка приложения: `NSApplicationDelegate`, `NSStatusItem`
    (иконка в menu bar), `NSMenu`, кастомный `NSPanel` для плавающего
    оверлея, низкоуровневая работа с событиями (`CGEvent`, `AXUIElement`).
  - SwiftUI — содержимое окон, где не нужен низкоуровневый контроль:
    Settings, окно истории, онбординг, а также содержимое оверлея (через
    `NSHostingView`/`NSHostingController`).
  - Причина гибрида: `MenuBarExtra`/чистый SwiftUI `Window` пока не дают
    полного контроля над уровнем окна, поведением "не забирать фокус",
    click-through и т.п. — это классический паттерн для таких утилит
    (Raycast, CleanShot X, Rewind и т.д.).
- **Минимальная версия macOS: 14 (Sonoma)+**
  - Открывает SwiftData для истории и `SMAppService` для автозапуска.
  - Fallback-путь, если понадобится более широкая поддержка: macOS 12+ с
    Core Data / SQLite вместо SwiftData (единственное место в архитектуре,
    которое реально завязано на версию ОС).

### 1.2 Глобальный хоткей
- Использовать пакет **`sindresorhus/KeyboardShortcuts`** (SPM), а не писать
  свой `RegisterEventHotKey`/`CGEventTap` с нуля.
  - Готовый SwiftUI-компонент `KeyboardShortcuts.Recorder` для экрана
    настроек — запись комбинации "из коробки", с защитой от конфликтов.
  - Не требует специальных entitlements, отлично работает вне sandbox.
- Одно основное действие: `KeyboardShortcuts.Name.toggleDictation`
  (старт/стоп по одному и тому же сочетанию — toggle-модель, а не
  push-to-talk).
- **Esc для отмены** — НЕ регистрируется как глобальный хоткей (это увело бы
  Esc из всей системы постоянно). Вместо этого: временный локальный
  监视 монитор клавиш активируется только пока идёт запись/обработка и
  снимается сразу после.
- Проверка конфликтов: пакет сам не даёт назначить системные комбинации;
  дополнительно — предупреждение в UI, если выбранная комбинация похожа на
  часто используемые системные (best-effort, полный список чужих биндингов
  недоступен).

### 1.3 Плавающий оверлей (индикатор микрофона)
- Кастомный `NSPanel` (`styleMask: [.borderless, .nonactivatingPanel]`) —
  **никогда** не забирает фокус/key window у текущего приложения (иначе
  вставка текста в исходное поле сломается).
  - `level = .floating` (или выше) — поверх всех обычных окон.
  - `collectionBehavior`: `.canJoinAllSpaces`, `.fullScreenAuxiliary` —
    виден даже поверх full-screen приложений и на других Spaces.
  - Прозрачный фон, `NSVisualEffectView` + SwiftUI-контент (капсула/шарик,
    похоже на системный HUD громкости или Siri-индикатор).
  - `ignoresMouseEvents = true` (click-through) — в v1 оверлей не
    интерактивен, управление только хоткеем/Esc.
- **Позиция:** низ по центру активного экрана (там же, где HUD громкости) —
  фиксированное значение для v1, настраиваемая позиция — задел на будущее.
- **Состояния и анимации** — см. раздел 2.3.
- Таймигни: fade-in ~150ms, переходы между состояниями ~200ms, автозакрытие
  после успеха ~600–1000ms, после ошибки — 2–3с (успевать прочитать) либо
  зависать до явного подтверждения для "конфигурационных" ошибок (см. 2.3).

### 1.4 Захват аудио
- **`AVAudioEngine`** (не `AVAudioRecorder`) — даёт доступ к живому уровню
  сигнала (для анимации волны) и гибкую конвертацию форматов через
  `AVAudioConverter`.
- Формат для отправки в OpenAI: **WAV, mono, 16 кГц, 16 бит** — по умолчанию
  для v1 (достаточно для распознавания речи, просто и детерминированно).
  m4a/AAC — возможная оптимизация позже (меньше вес аплоада), не критично
  для коротких клипов.
- Защитные механизмы:
  - **Жёсткий лимит длительности** (например, 120 секунд) — авто-стоп и
    переход к распознаванию.
  - **Опциональный авто-стоп по тишине** (N секунд подряд ниже порога после
    минимальной длительности речи) — выключен по умолчанию, включается в
    настройках как доп. режим (основной способ остановки — повторное
    нажатие хоткея).
  - Если за всё время записи не было значимого сигнала — не отправлять
    почти-тишину в API, сразу показать состояние "ничего не расслышано".
  - Минимальная длительность записи (например, 300мс) — защита от случайного
    двойного нажатия, трактуется как отмена.

### 1.5 Сетевой слой (OpenAI Transcription API)
- `POST https://api.openai.com/v1/audio/transcriptions`,
  `multipart/form-data`: `file`, `model`, опционально `language`,
  `response_format` (`json`/`text` — нам нужен только сырой текст, без
  таймкодов/сегментов).
- Заголовок `Authorization: Bearer <ключ>`, ключ читается из Keychain
  непосредственно перед вызовом (никогда не логируется, никогда не лежит в
  открытом виде).
- **Архитектура выбора модели** — enum `TranscriptionModel`
  (`gpt4oTranscribe` / `gpt4oMiniTranscribe` / `whisper1`) с описанием
  возможностей каждой модели (макс. размер файла, поддерживаемые
  `response_format` и т.д.) — сетевой слой строит запрос по этой
  конфигурации, а не хардкодит одну модель. Добавление новой модели —
  просто новый case enum.
- `URLSession` с адекватными таймаутами (connect ~30с, resource ~60с),
  многочастное тело собирается вручную (без сторонних сетевых библиотек —
  один эндпоинт, простая логика).
- **Обработка ошибок и повторные попытки:**
  - Классы ошибок: нет сети, таймаут, 401 (неверный ключ), 429
    (rate limit/квота), 5xx (ошибка сервера), 400 (некорректный
    запрос/формат/размер), пустой текст в ответе 200.
  - Авто-ретрай (1–2 попытки, короткий backoff) — только для
    транзиентных классов (таймаут, 429 с учётом `Retry-After`, 5xx).
    401/400 — без ретрая, это не исправится само.
  - Отмена (Esc) во время сетевого запроса — немедленная отмена
    `URLSessionTask`.

### 1.6 Буфер обмена и вставка текста в позицию курсора
- **Буфер обмена:** всегда безусловно — `NSPasteboard.general`.
- **Вставка — двухуровневый подход:**
  1. **Основной способ: Accessibility API (`AXUIElement`).** Получить
     сфокусированный элемент фронтового приложения
     (`kAXFocusedUIElementAttribute`), если он поддерживает
     `kAXValueAttribute`/`kAXSelectedTextRangeAttribute` — вставить текст
     напрямую в позицию курсора через `AXUIElementSetAttributeValue`.
     Работает не во всех приложениях (особенно Electron/веб-редакторы) —
     считается best-effort.
  2. **Fallback: синтетический Cmd+V через `CGEvent`.** Буфер обмена уже
     содержит текст → эмулируется нажатие Cmd+V (`CGEvent` в
     `.cghidEventTap`) — так же работает большинство утилит вроде Alfred,
     Raycast, TextExpander (требует того же самого Accessibility-доверия).
  - Перед вставкой — проверка (best-effort через AX), что фокус не
    "уехал" в другое приложение с момента начала записи; если поле для
    вставки вообще не определено (например, фронтовое приложение — Finder)
    — вставка пропускается полностью, остаётся только копирование в буфер
    с соответствующим сообщением в оверлее.
  - **И основной, и резервный способ требуют разрешения Accessibility** —
    без него доступна только работа "скопировано в буфер, без автовставки".
    Онбординг явно запрашивает это разрешение с deep-link в System
    Settings и живым опросом `AXIsProcessTrusted()`.
- **Настройка пользователя:** "всегда вставлять в курсор" vs "только
  копировать в буфер, без автовставки"; плюс предпочтение способа вставки
  (авто / только Accessibility / только keystroke) для продвинутых
  пользователей.
- **Защита для секретных полей:** если сфокусированное поле определяется
  через AX как защищённое текстовое поле (пароль) — автовставка
  пропускается (копирование в буфер остаётся), чтобы не печатать
  распознанный текст в поле пароля по ошибке.

### 1.7 Хранение ключа OpenAI
- **Keychain Services** — generic password item, привязанный к bundle ID
  приложения. Никогда не пишется в `UserDefaults`/plist/логи.
- Читается в память только в момент вызова API и для отображения (маской)
  в настройках.
- В настройках: поле ввода (`SecureField`), кнопка "Проверить" (лёгкий
  запрос-валидация ключа, отдельно от "Невалидный ключ"/"Ошибка сети").

### 1.8 Окно настроек
- Кастомное окно (`NSWindowController` + `NSHostingController`), а не
  стандартная SwiftUI `Settings {}`-сцена — в LSUIElement-приложении без
  Dock-иконки стандартная сцена не всегда надёжно выходит на передний план;
  явно вызываем `NSApp.activate` + `makeKeyAndOrderFront`.
- Вкладки: General / Hotkey / OpenAI / Insertion Behavior / Privacy (см.
  раздел 2.6).

### 1.9 Локальное хранилище истории
- **SwiftData** (macOS 14+) — модель `HistoryEntry` как `@Model`,
  `@Query` для живого списка/поиска/сортировки в SwiftUI напрямую.
  Fallback при необходимости — Core Data или SQLite (GRDB).
- Хранится в `~/Library/Application Support/<BundleID>/`, без iCloud-синка
  в v1.
- Политика хранения (настраиваемая): "хранить всегда" (по умолчанию) /
  "последние N дней" (7/30/90) / "последние N записей" — очистка по
  таймеру при запуске и раз в сутки.

### 1.10 Автозапуск и жизненный цикл приложения
- Автозапуск — `SMAppService.mainApp.register()/.unregister()` (без
  отдельного helper-приложения).
- `LSUIElement = true` — без иконки в Dock, без пункта в свитчере
  приложений; управление только через `NSStatusItem`.
- При запуске окна не открываются (кроме первого запуска — онбординг).
- Выход из приложения — только через явный пункт "Quit" в меню статус-бара.
- Звуковая обратная связь (`NSSound`/системные звуки): старт записи, успех,
  ошибка — три разных коротких тона, с общим тумблером вкл/выкл в
  настройках. Тактильной обратной связи не будет — не применимо к Mac
  (в отличие от iOS Taptic Engine).

### 1.11 Сводный список обрабатываемых ошибок
1. Нет подключения к интернету.
2. Отсутствующий/невалидный/отозванный API-ключ (разные сообщения для
   "не настроен" и "отклонён сервером").
3. Ошибка/лимит OpenAI API (429/5xx).
4. Нет разрешения на микрофон (проверяется ДО попытки записи).
5. Нет разрешения Accessibility (влияет только на автовставку, не на
   запись/распознавание/копирование — деградация до "только буфер").
6. Пустой результат распознавания (тишина или пустой ответ от API) —
   отдельное "нейтральное" состояние, не ошибка.
7. Микрофон не найден/отключён.
8. Файл/длительность превышают лимиты модели (защитный кейс, обычно
   предотвращается лимитом длительности).
9. Отмена пользователем (Esc) — отдельное терминальное состояние, не
   логируется как ошибка.

## 2. Детальный функционал по модулям

### 2.1 Первый запуск — онбординг
Показывается автоматически при первом запуске (флаг
`hasCompletedOnboarding`), позже доступен повторно из меню/настроек
("Setup Wizard…").

1. **Экран приветствия** — название, иконка, короткое описание, кнопка
   "Начать".
2. **Разрешение на микрофон** — объяснение зачем, кнопка запроса
   (`AVCaptureDevice.requestAccess`), живой статус, deep-link в System
   Settings при отказе, кнопка "Проверить снова". Нельзя продолжить без
   этого разрешения (это ядро функции), но есть "Пропустить" с
   постоянным предупреждающим баннером далее.
3. **Разрешение Accessibility** — объяснение (нужно для автовставки, без
   него — только копирование в буфер), кнопка "Открыть System Settings",
   живой опрос `AXIsProcessTrusted()`. Можно пропустить (это опциональный,
   деградируемый режим).
4. **Ввод API-ключа OpenAI** — поле ввода (маскированное), ссылка "где
   взять ключ", кнопка "Проверить ключ". Можно пропустить с пометкой
   "добавить позже в настройках" + постоянный бейдж-напоминание в
   статус-баре.
5. **Настройка хоткея** — `KeyboardShortcuts.Recorder`, предзаполненный
   разумным дефолтом (не конфликтующим с ⌘Space/Spotlight), можно сразу
   изменить.
6. **Завершение** — короткое резюме "как это работает", кнопка "Готово"
   (ставит `hasCompletedOnboarding = true`), опционально — кнопка
   "Попробовать сейчас" (запускает реальный цикл записи прямо в
   онбординге).
7. Если пользователь закрыл онбординг не закончив — при следующем запуске
   онбординг просто начинается заново с первого экрана (без сохранения
   прогресса по шагам — этого достаточно для v1).

### 2.2 Иконка в строке меню и выпадающее меню
- **Состояния иконки** (шаблонное изображение, адаптируется под
  тёмную/светлую тему):
  - Обычное (простой значок микрофона).
  - Идёт запись (выделенный/подсвеченный вариант, лёгкая пульсация —
    без тяжёлой анимации).
  - Идёт распознавание (иконка-спиннер/отдельный вид).
  - Требует внимания (маленький бейдж — например, не настроен ключ или не
    выданы разрешения).
- **Пункты меню:**
  - Строка статуса (необязательно, "Ожидание" / "Запись…" / "Распознавание…").
  - "Начать запись" / "Остановить запись" (текст меняется по состоянию —
    дублирует хоткей для тех, кто предпочитает мышь).
  - Разделитель.
  - "Открыть историю…"
  - "Настройки…"
  - Разделитель.
  - "О приложении" (версия, ссылка на поддержку/changelog).
  - Разделитель.
  - "Выход" (с акселератором ⌘Q).
- Клик по иконке — стандартное открытие меню `NSStatusItem`.

### 2.3 Состояния и переходы оверлея записи
- **Idle** — оверлей не существует/скрыт, никакого визуального следа.
- **Idle → Listening** (запуск по хоткею или из меню): оверлей появляется
  почти мгновенно (цель — восприятие <100мс), одновременно стартует
  захват аудио. Fade-in, начинает анимироваться волна по уровню сигнала.
  Звук старта (если включён).
- **Listening (в процессе):** непрерывная анимация волны/уровня,
  подпись "Слушаю…" и/или счётчик прошедшего времени. При приближении к
  лимиту длительности — визуальное предупреждение (смена цвета).
- **Listening → Transcribing:** повторное нажатие хоткея, либо
  авто-стоп по лимиту длительности, либо (если включено) авто-стоп по
  тишине. Захват останавливается, оверлей превращается в
  индикатор обработки (спиннер/пульсирующие точки), уходит сетевой запрос.
- **Transcribing → Success:** копирование в буфер сразу по получении
  текста → попытка вставки в курсор (AX, затем CGEvent) → сохранение
  записи в историю → короткая "галочка" на оверлее → звук успеха →
  автозакрытие через ~600–1000мс.
- **Transcribing → пустой результат:** отдельное нейтральное состояние
  ("Не расслышал"), без иконки ошибки. Ничего не копируется/не
  вставляется. Рекомендация: НЕ сохранять такие попытки в историю (чтобы
  история оставалась содержательной), автозакрытие через ~1.5–2с.
- **Transcribing → Error:** иконка ошибки + короткое человекочитаемое
  сообщение (маппинг из списка 1.11: "Нет подключения к интернету",
  "Неверный API-ключ — проверьте настройки", "Превышен лимit OpenAI,
  попробуйте позже", "Микрофон не найден" и т.д.). Звук ошибки. Запись в
  историю со статусом "ошибка" + причина.
  - Транзиентные ошибки (сеть, rate limit) — автозакрытие через 2–3с.
  - Конфигурационные ошибки (неверный ключ, нет разрешения) — оверлей
    остаётся до явного подтверждения/клика + дублируется системным
    уведомлением (macOS notification), так как оверлей могли не заметить.
- **Любое активное состояние → Cancelled (Esc):** мгновенное исчезновение,
  без сохранения в историю, без сетевого запроса (если был в Listening)
  или отмена уже идущего запроса (если был в Transcribing).
- Автозакрытие всегда прерывается новым нажатием хоткея — немедленно
  начинается новый цикл Listening, без "очереди".

### 2.4 Управление записью
- **Старт:** глобальный хоткей (из любого приложения) в состоянии Idle;
  либо пункт "Начать запись" в меню.
- **Стоп (обычный):** тот же хоткей повторно во время Listening
  (toggle-модель, не push-to-talk).
- **Отмена:** Esc во время Listening или Transcribing — без сохранения/
  вставки.
- **Авто-стоп по лимиту:** жёсткий таймер (например, 120с).
- **Авто-стоп по тишине (опционально):** включается в настройках,
  выключен по умолчанию.
- **Защита от повторного входа:** нажатие хоткея во время Transcribing
  игнорируется (не прерывает уже идущий запрос) — прервать его можно
  только явно через Esc.

### 2.5 Пайплайн распознавания (сквозной сценарий)
1. Запись аудио завершена (буфер/файл готов).
2. Предварительные проверки: есть ли API-ключ? (Если нет — сразу, не
   начиная запись вообще, показать ошибку — "не тратить" дыхание
   пользователя впустую.)
3. Сборка multipart-запроса: файл + модель (из настроек) + опциональная
   подсказка языка + `response_format`.
4. Отправка запроса, немедленный показ состояния "Распознавание…".
5. Успех (непустой текст): нормализация только пробелов/переносов (никакой
   другой обработки — без GPT-очистки) → буфер обмена → попытка вставки
   в курсор с учётом настройки поведения вставки → определение
   фронтового приложения (`NSWorkspace.frontmostApplication`) для метаданных
   истории → сохранение записи → состояние Success → звук.
6. Успех, но пустой текст: состояние "пустой результат", буфер не
   трогается, запись в историю не создаётся (по умолчанию).
7. Ошибка (любой класс из 1.11): состояние Error с сообщением, звук
   ошибки, запись в историю со статусом "ошибка" + причина.
8. Отмена: обрыв запроса, никаких побочных эффектов.
9. Очистка: временный аудиофайл удаляется сразу после завершения запроса
   (успех/ошибка/отмена) — аудио никогда не хранится дольше, чем
   требуется для загрузки.

### 2.6 Окно настроек — 5 вкладок

**General:**
- Тумблер "Запускать при входе в систему" (`SMAppService`).
- Тумблер "Звуковые эффекты" (общий вкл/выкл для старт/успех/ошибка).
- Тумблер "Показывать прошедшее время в оверлее".
- Кнопка "Повторить мастер настройки" (перезапуск онбординга).
- Версия/сборка приложения, кнопка "Проверить обновления" (см. 4.4 —
  Sparkle framework).

**Hotkey:**
- `KeyboardShortcuts.Recorder`, привязанный к `.toggleDictation`.
- Предупреждение о потенциальных конфликтах с системными сочетаниями.

**OpenAI:**
- Поле API-ключа (`SecureField`), тумблер "показать/скрыть", кнопка
  "Проверить", кнопка "Удалить ключ".
- Выбор модели: `gpt-4o-transcribe` (по умолчанию) /
  `gpt-4o-mini-transcribe` / `whisper-1`, с коротким описанием
  компромисса скорость/цена/точность для каждой.
- Подсказка языка (код ISO-639-1 или "Автоопределение" по умолчанию).
- Информационная ссылка на тарифы OpenAI (пользователь платит своим
  ключом).

**Insertion Behavior:**
- Тумблер: "Всегда вставлять в курсор" vs "Только копировать в буфер".
- Предпочтение способа вставки: Авто (AX → CGEvent) / только
  Accessibility API / только keystroke-эмуляция.
- Пропуск автовставки в поля паролей — всегда включено (не выключается
  пользователем, это защита по умолчанию).

**Privacy:**
- Политика хранения истории: "хранить всегда" (по умолчанию) /
  "последние 7 дней" / "последние 30 дней" / "последние 90 дней" /
  "последние N записей".
- Кнопка "Очистить всю историю сейчас" (с подтверждением).
- Информационная строка: "Аудиозаписи отправляются в OpenAI для
  распознавания и не хранятся локально после обработки."
- (Отложено на будущее, не в v1) опция "сохранять аудио локально вместе
  с текстом" — по умолчанию выключена/отсутствует, так как противоречит
  требованию "только сырая расшифровка, без лишнего хранения".

### 2.7 Окно истории
- **Список** (обратный хронологический порядок): усечённый текст,
  относительное время ("2 минуты назад" / точная дата при наведении),
  иконка успех/ошибка, иконка приложения, куда была вставка (если
  известно).
- **Поиск/фильтр:** поле поиска по тексту (подстрока), переключатель
  "показывать только ошибки".
- **Действия по записи** (контекстное меню/кнопки при наведении):
  - "Копировать" — заново в буфер.
  - "Копировать и вставить снова" — копирует и пытается вставить в
    текущее фронтовое приложение (AX/CGEvent пайплайн).
  - "Удалить" (без подтверждения — низкий риск для одной записи).
  - "Подробнее" — полный текст, точное время, длительность, модель,
    приложение назначения, статус, причина ошибки (если есть).
- **Массовые действия:**
  - "Очистить всю историю" — с обязательным подтверждением ("Будет
    удалено N записей безвозвратно").
  - (Опционально) множественный выбор + "Удалить выбранное".
- **Экспорт** (желательно, не критично): экспорт в текстовый файл через
  `NSSavePanel`; CSV/JSON — по возможности, не обязательно для v1.
- **Пустое состояние:** "Записей пока нет — нажмите [хоткей], чтобы
  начать".

### 2.8 Восстановление после ошибок разрешений
- **Нет разрешения на микрофон** (отозвано после онбординга): при
  попытке записи — короткая ошибка на оверлее + системное уведомление с
  действием "Открыть System Settings"; постоянный бейдж на иконке
  статус-бара, пока не исправлено.
- **Нет разрешения Accessibility:** не блокирует запись/распознавание/
  копирование — только автовставку. После успешного распознавания без
  автовставки оверлей показывает "Скопировано в буфер" (а не обычную
  галочку успеха), чтобы было понятно, почему не вставилось. Ненавязчивое
  периодическое напоминание (не чаще раза в день) с прямой ссылкой на
  включение разрешения.
- **Невалидный/отсутствующий ключ:**
  - Отсутствует полностью — ошибка показывается сразу при нажатии
    хоткея, ДО начала записи (проверка до открытия микрофона).
  - Есть, но отклонён (401) — обнаруживается только в момент вызова;
    ошибка "Неверный API-ключ", уведомление с действием "Открыть
    настройки", запись в историю.
- **Нет сети:** ошибка "Нет подключения к интернету", автоматический
  повтор для временных сбоев, финальная ошибка после исчерпания попыток.

### 2.9 Системные уведомления
- Используются только для ситуаций, требующих действия пользователя
  (проблемы с ключом/разрешениями) — НЕ для каждого успешного
  распознавания (было бы избыточно, оверлей+звук уже покрывают этот
  случай).
- С действиями (`UNNotificationAction`), например "Открыть настройки".
- Уважают системный режим "Не беспокоить"/Focus (поведение по умолчанию).
- Запрос разрешения на уведомления — не в онбординге (чтобы не
  перегружать пользователя разрешениями сразу), а лениво, в момент первой
  реальной необходимости (первая конфигурационная ошибка).

## 3. Модели данных (концептуально)

### 3.1 `AppSettings` (несекретные поля — `UserDefaults`/`@AppStorage`; ключ API — только Keychain)
- `launchAtLoginEnabled: Bool`
- `soundEffectsEnabled: Bool`
- `showElapsedTimeInOverlay: Bool`
- `selectedTranscriptionModel: TranscriptionModel`
- `languageHint: String?`
- `insertionMode: .alwaysPasteAtCursor | .clipboardOnly`
- `pasteMethodPreference: .auto | .accessibilityPreferred | .keystrokeOnly`
- `historyRetentionPolicy: .forever | .days(Int) | .lastNEntries(Int)`
- `maxRecordingDurationSeconds: Int` (по умолчанию 120)
- `silenceAutoStopEnabled: Bool` (по умолчанию false)
- `hasCompletedOnboarding: Bool`

### 3.2 `HistoryEntry` (SwiftData `@Model`)
- `id: UUID`
- `timestamp: Date`
- `transcribedText: String`
- `durationSeconds: Double`
- `modelUsed: String` (сохраняется как значение на момент записи, не
  ссылка на текущую настройку)
- `targetAppBundleIdentifier: String?`
- `targetAppDisplayName: String?`
- `insertionOutcome: .pastedViaAccessibility | .pastedViaKeystroke | .clipboardOnlyNoPaste | .clipboardOnlyUserPreference | .notAttempted`
- `status: .success | .failure | .cancelled`
- `errorReason: String?` (только при `.failure`)

### 3.3 `RecordingState` (in-memory, управляет UI оверлея и иконкой)
- `.idle`
- `.listening(startedAt, currentLevel)`
- `.transcribing(audioDuration)`
- `.success(text)`
- `.emptyResult`
- `.error(reason, isConfigurationError)`
- `.cancelled`

### 3.4 `TranscriptionModel` (конфигурационный enum)
- `.gpt4oTranscribe`, `.gpt4oMiniTranscribe`, `.whisper1` — каждый с
  идентификатором модели API, отображаемым именем, кратким описанием,
  поддерживаемыми `response_format`.

## 4. Нефункциональные требования

### 4.1 Приватность
- Аудио живёт только временно (память/временный файл) на время одного
  запроса, удаляется сразу после завершения — независимо от результата.
- Локально сохраняется только текст + лёгкие метаданные (длительность,
  время, приложение, модель) — не аудио.
- Ключ API уходит только напрямую в `api.openai.com` через TLS — никакого
  собственного бэкенда/прокси в архитектуре нет.
- Текст временно оказывается в системном буфере обмена (неизбежное
  следствие требуемого поведения) — стоит одной строкой упомянуть это в
  онбординге/настройках.

### 4.2 Безопасность API-ключа
- Только Keychain, никогда — `UserDefaults`/plist/логи/краш-репорты.

### 4.3 Производительность (задержка хоткея)
- Цель: <100мс от нажатия до видимого/пишущего оверлея.
- Оверлей (`NSPanel`) создаётся один раз при запуске (скрытым) и
  переиспользуется — не пересоздаётся каждый раз.
- Регистрация хоткея через Carbon (внутри `KeyboardShortcuts`) — сама по
  себе фактически мгновенная, узкое место — старт аудиодвижка и показ
  окна.

### 4.4 Нотариизация, подпись, entitlements
- Приложение подписывается Developer ID, нотариизируется через
  `notarytool`, упаковывается в DMG (обычный не-MAS флоу).
- **Без App Sandbox** — сознательный выбор, иначе сломается работа
  CGEvent/AX с чужими процессами.
- Специальных entitlements для Accessibility не требуется — это
  TCC-разрешение (Privacy & Security), не запись в `entitlements.plist`.
  `com.apple.security.automation.apple-events` НЕ нужен — это для
  AppleScript/Apple Events, у нас другой механизм (AX + CGEvent).
- Hardened Runtime — включён, без специальных исключений.
- `NSMicrophoneUsageDescription` в `Info.plist` — обязательное
  человекочитаемое объяснение для системного запроса разрешения.
- **Автообновления:** рекомендуется framework **Sparkle** (стандарт для
  Developer-ID-приложений вне App Store) — заложить архитектурно с самого
  начала, тяжелее добавлять постфактум.

### 4.5 Минимальная версия macOS
- **macOS 14 (Sonoma)+** — рекомендовано, ради SwiftData и современных
  API. Единственная развилка по версии во всей архитектуре — SwiftData
  vs Core Data/SQLite; всё остальное (AVAudioEngine, AX API,
  NSPasteboard, Keychain, KeyboardShortcuts, UNUserNotificationCenter)
  работает начиная примерно с macOS 10.15/11.

## 6. Ориентировочная структура проекта (для будущей реализации)

Ключевые модули, которые нужно спроектировать первыми (это ядро, вокруг

  multipart-загрузки, параметризованный `TranscriptionModel`.
- `Insertion/TextInsertionService.swift` — логика AX → CGEvent вставки и
  деградации до буфера обмена (самая хрупкая часть системы).
- `Persistence/HistoryStore.swift` — SwiftData-контейнер и схема
  `HistoryEntry`, политика хранения/очистки.
